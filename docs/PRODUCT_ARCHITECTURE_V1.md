# AI B超报告书写助手 V1 — 产品架构

## 1. 系统架构

```
┌─────────────────────────────────────────────────────────────┐
│                    AI B超报告书写助手                          │
└─────────────────────────────────────────────────────────────┘
                              │
              ┌───────────────▼───────────────┐
              │         医生语音输入           │
              └───────────────┬───────────────┘
                              ↓
              ┌───────────────┐
              │  Medical ASR  │  医疗语音识别
              └───────┬───────┘
                      ↓
              ┌───────────────┐
              │   原始文本     │
              └───────┬───────┘
                      ↓
              ┌───────────────┐
              │  LLM 理解层   │  医学信息抽取 → B超结构化 JSON
              └───────┬───────┘
                      ↓
              ┌───────────────┐
              │ B超 Schema   │
              └───────┬───────┘
                      ↓
         ┌────────────┴────────────┐
         ↓                         ↓
  ┌─────────────┐          ┌─────────────┐
  │ 报告模板库  │          │  校验规则   │
  └──────┬──────┘          └──────┬──────┘
         └────────────┬────────────┘
                      ↓
              ┌───────────────┐
              │   报告生成     │  超声所见 + 超声提示
              └───────┬───────┘
                      ↓
              ┌───────────────┐
              │  医生审核修改  │  修改记录 + 高亮
              └───────┬───────┘
                      ↓
                   最终报告
```

## 2. LLM 工作流

### 2.1 阶段一：口述 → 结构化 JSON

**输入**：ASR 原始文本 + Schema 定义（Few-shot 来自 Gold Dataset）

**Prompt 结构**：

```
你是超声报告结构化助手。将医生口述的检查所见转为 JSON，严格遵循 Schema。
不要诊断，只抽取所见。不确定的字段标 uncertainty: true。
数值必须带单位。未提及的器官 omit，不要填「正常」。

Schema: {schema_json}
Few-shot: {gold_examples}
医生口述: {asr_text}
```

**输出**：符合 `abdominal_ultrasound.json` Schema 的 JSON

### 2.2 阶段二：结构化 JSON → 报告文本

**输入**：结构化 JSON + 报告模板

**方式**：**规则模板优先**（非 LLM），保证术语一致、可控

```
模板引擎:
  遍历 organ → 按字段顺序拼接标准句式
  病灶单独段落
  超声提示: 从 impression_hints 或病灶类型映射
```

LLM 润色 **V1 不做**。

### 2.3 阶段三：校验

**输入**：结构化 JSON

**规则引擎**（见 `validation_rules/abdominal.json`）：

- 数值范围（胆总管 >10mm 告警）
- 左右对称性
- 必填项完整性
- 矛盾检测（如「结石」+「无声影」）

**输出**：`warnings[]` + `highlights[]`

## 3. 页面设计

### 3.1 主工作区（三栏对照）

```
┌──────────────────────────────────────────────────────────────────┐
│  AI B超报告书写助手    [腹部超声 ▼]    [🎙 开始录音]  [保存草稿]  │
├──────────────────┬──────────────────┬────────────────────────────┤
│ 🎙 医生原话       │ 🤖 AI 识别       │ 📄 生成报告                 │
│                  │                  │                            │
│ ASR 实时/回放    │ 树形 Schema 视图 │ 超声所见（可编辑）          │
│                  │ 可点击字段修改   │ 超声提示（可编辑）          │
│ "胆囊里一个六    │                  │                            │
│  毫米强回声..."  │ 胆囊             │ 胆囊大小正常，壁不厚，      │
│                  │  └ 病灶: 强回声  │ 腔内可见约6mm强回声...     │
│                  │  └ 大小: 6 mm ⚠  │                            │
│                  │  └ 移动: 不移动  │ ⚠ 胆总管 8mm 请确认       │
├──────────────────┴──────────────────┴────────────────────────────┤
│ 修改记录: 大小 6mm→5mm (医生)  14:32                              │
└──────────────────────────────────────────────────────────────────┘
```

### 3.2 核心交互

| 操作 | 行为 |
|------|------|
| 点击 Schema 字段 | 高亮对应报告段落，可 inline 编辑 |
| 编辑报告文字 | 反向更新 Schema（可选 V1.1） |
| ⚠ 校验告警 | 必须确认或修改后才能签发 |
| 签发 | 写入报告系统 + 记录 diff |

### 3.3 页面清单（V1）

| 页面 | 功能 |
|------|------|
| `/report/new` | 新建报告（主工作区） |
| `/report/{id}` | 查看/编辑已有报告 |
| `/report/{id}/history` | 修改记录 |
| `/admin/templates` | 模板管理（内部） |
| `/admin/gold-dataset` | Gold Dataset 管理（内部） |

## 4. 数据模型

### 4.1 Report（报告）

```json
{
  "id": "uuid",
  "exam_type": "abdominal_ultrasound",
  "status": "draft | reviewing | signed",
  "asr_text": "医生原话",
  "structured": { /* Schema JSON */ },
  "findings_text": "超声所见",
  "impression_text": "超声提示",
  "warnings": [],
  "created_at": "ISO8601",
  "signed_at": null,
  "doctor_id": "..."
}
```

### 4.2 EditRecord（修改记录）

```json
{
  "report_id": "uuid",
  "field_path": "gallbladder.lesions[0].size_mm",
  "old_value": "6",
  "new_value": "5",
  "source": "doctor | ai",
  "timestamp": "ISO8601"
}
```

## 5. API 设计（V1）

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/asr/stream` | POST | 语音流 → 文本 |
| `/api/structure` | POST | 文本 → 结构化 JSON |
| `/api/report/generate` | POST | JSON → 报告文本 + 校验 |
| `/api/report` | POST/GET/PATCH | CRUD |
| `/api/report/{id}/sign` | POST | 签发 |
| `/api/report/{id}/edits` | GET | 修改记录 |

## 6. 技术选型建议

| 层 | 建议 |
|----|------|
| ASR | 讯飞/阿里医疗 ASR 或 Whisper + 医学热词 |
| LLM | 结构化抽取用 JSON mode；国内可用通义/DeepSeek |
| 模板 | Jinja2 或自研规则引擎 |
| 校验 | 独立规则引擎，不依赖 LLM |
| 前端 | Vue3 + 三栏布局 |
| 后端 | FastAPI（与现有项目风格一致） |
